# XStar Guitar UI 设计基线

## 1. 设计目标

首版界面围绕一个核心问题组织：用户打开应用后，能否立即知道下一步做什么，并在练习后自然回到学习路径。

设计目标：

- 让零基础用户在 3 次主要点击内开始第一课或调音。
- 每个任务页只保留一个高优先级行动。
- 工具页首先给动作建议，再显示专业参数。
- 课程、练习、和弦和曲谱使用一致的能力与进度语言。
- 不依赖颜色表达音准、节拍、完成或错误状态。
- 手机单栏和宽屏双栏共享同一内容与导航层级。

## 2. 视觉概念

### 2.1 方向：沉浸式数字练习室

视觉灵感来自舞台灯光、琴弦振动和数字调音设备，但不直接拟物化。默认使用深色低反光画布、半透明表面、细描边和局部极光渐变；内容区块依靠明度与空间划分，不依靠大量不同颜色。

整体气质：

- 现代、冷静且有音乐氛围。
- 酷炫，但不牺牲专业工具的读数清晰度。
- 有节奏感，但不使用强游戏化反馈。
- 内容密度克制，避免大面积空洞卡片。

### 2.2 视觉母题

- 六根弦：细线、分隔、进度轨道和调音刻度采用六弦意象。
- 品格：局部使用规律横线组织步骤和进度，不做完整拟物指板。
- 拨片：主要按钮、状态标签和部分插图使用不完全对称的圆角轮廓。
- 谱纸：课程与曲谱内容使用接近纸张的暖白内容面。

## 3. 颜色与主题系统

首版支持预设主题与自定义主题。主题通过语义 Token 切换，不允许页面组件直接依赖某套主题的固定颜色；工具状态色在不同主题中保持一致语义和必要对比度。

### 3.1 预设主题

| 主题 | 画布与表面 | 强调色 | 气质 |
|---|---|---|---|
| 极光夜 | 深蓝黑、半透明冷灰 | 电光紫蓝 | 默认，沉浸、现代 |
| 暖木 | 暖白、浅木灰 | 琥珀棕 | 温和、自然 |
| 冰川 | 浅冷灰、纯白 | 冰蓝 | 清晰、轻量 |
| 自定义 | 用户选择明暗基底 | 用户选择强调色 | 个性化 |

主题设置提供实时预览，保存到本地并在下次启动恢复。切换主题不应重建正在运行的调音或练习会话。

### 3.2 语义 Token

| Token | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `canvas` | `#F4F0E8` | `#151816` | 应用背景 |
| `surface` | `#FFFDF7` | `#202420` | 内容面、卡片 |
| `surfaceMuted` | `#EAE4D9` | `#2A302B` | 次级区域、轨道 |
| `ink` | `#1B211D` | `#F2F0E8` | 主文字 |
| `inkMuted` | `#687169` | `#AEB8AF` | 辅助信息 |
| `brand` | `#9B4B2C` | `#E68A62` | 主要行动、当前路径 |
| `brandStrong` | `#71351F` | `#FFAD85` | 按压、高对比强调 |
| `steady` | `#147D73` | `#58C9BB` | 调准、稳定、完成 |
| `attention` | `#B76A08` | `#F4B45D` | 偏差、需注意 |
| `danger` | `#B13D3D` | `#FF8B86` | 不可恢复错误 |
| `outline` | `#D2C9BC` | `#414A43` | 边框、分隔 |

规则：

- “已调准”同时使用 `steady`、勾形图标和文字。
- 偏低与偏高同时使用方向箭头、位置和文字，不能只使用冷暖色。
- 主按钮只使用 `brand`，避免一个页面出现多个同权重实心按钮。
- 大面积背景不使用高饱和品牌色，长时间练习时降低视觉疲劳。
- 渐变只用于背景氛围和主行动边缘，不作为文字底色或状态含义。
- 同一页面最多使用一个强调色和一组状态色，区块主要靠表面层级划分。

### 3.3 自定义能力

- 可选择极光夜、暖木、冰川三个预设主题。
- 可自定义强调色，并实时生成按钮、当前项、进度和焦点色。
- 可选择紧凑或舒展内容密度。
- 可关闭背景光晕与半透明效果。
- 可跟随系统深浅模式，并单独开启减少动画。
- 自定义颜色必须通过正文、按钮和焦点态的对比度检查；不合格时给出建议而不是静默保存。

## 4. 字体与数字

Android 实现优先使用系统可用字体，避免首包因字体文件明显增大。

| 样式 | 建议规格 | 用途 |
|---|---|---|
| Display | 40sp / 44sp / 700 | BPM、当前音名、关键结果 |
| Headline | 28sp / 34sp / 700 | 页面标题 |
| Title | 20sp / 26sp / 650 | 卡片标题、当前动作 |
| Body | 16sp / 24sp / 400 | 正文、说明 |
| Label | 13sp / 18sp / 600 | 标签、元数据、导航 |
| Numeric | 等宽数字 | BPM、频率、计时、音分 |

规则：

- 标题避免口号化，直接说明任务。
- 数字变化时使用等宽数字，防止调音和计时界面跳动。
- 最大字体下允许卡片增高，不设置会裁切正文的固定高度。

## 5. 形状、间距与层级

- 基础间距单位：4dp。
- 页面水平边距：Compact 20dp，Medium 28dp，Expanded 32dp。
- 卡片内边距：16dp 或 20dp。
- 卡片圆角：20dp；小控件圆角：12dp；主要按钮圆角：16dp。
- 主要触控目标最小 48dp。
- 默认不使用明显投影，以边框、背景差和局部 1dp 阴影区分层级。
- 页面最大内容宽度 1120dp；正文阅读宽度控制在 680dp 左右。

## 6. 图标与插图

- 图标采用 2dp 圆角线性风格，选中态可增加局部填充。
- 不使用吉他、火焰、奖杯等图标替代明确文字。
- 教学插图以动作可读性优先，手指、琴弦和方向必须在灰度下仍可辨认。
- 空状态插图只用于解释，不占据首屏主要空间。

## 7. 全局导航

### 7.1 右侧导航抽屉

所有窗口尺寸均不使用底部导航或常驻 Navigation Rail。今天、学习、练习、曲谱和工具收进右侧导航抽屉，让任务页面保持完整、安静的内容画布。

- 每个一级页面右上角提供不小于 48dp 的明确菜单按钮，不能只依赖手势。
- 点击菜单按钮后，抽屉从右侧进入；点击遮罩、按返回键或向右滑动关闭。
- 可从屏幕右边缘向左滑动打开；该手势只是快捷方式，不承担功能发现。
- 抽屉宽度为窗口宽度的 82%，Compact 最大 360dp，Medium/Expanded 最大 400dp。
- 菜单显示完整文字标签和简短任务说明，当前页面使用品牌色边框、底色和“当前”文字共同标记。
- 设置、隐私和数据管理放在抽屉底部，与五个主要任务入口分组。
- 切换页面后立即关闭抽屉，并将无障碍焦点移到新页面标题。
- 曲谱阅读、练习会话和调音器等专注页面仅保留返回或退出，不显示菜单按钮。

### 7.2 Medium / Expanded

- 导航仍使用右侧抽屉，不因窗口变宽而常驻，确保主页与内容页保持一致的干净画布。
- Medium 主内容单列或列表详情切换。
- Expanded 可使用列表 + 详情，或主任务 + supporting pane。
- 页面内容居中并限制最大宽度，不使用导航留白填满屏幕。
- 不因宽屏增加无关卡片；新增空间优先展示上下文、诊断和下一步。

### 7.3 首版验证

五项入口保留在导航抽屉中。可用性测试重点记录：

- 用户是否能区分“学习”和“练习”。
- 用户寻找调音器时是否首先选择“工具”。
- 用户是否理解“今天”是默认下一步，而非统计面板。
- 用户是否能在未提示时找到右上角菜单，并从任意页面返回“今天”。

若 5 名零基础用户中有 2 名以上找不到菜单，需要增强按钮文字或在首次使用时提供一次性提示；若持续混淆“学习/练习”，则将练习并入学习，改为四项入口。

## 8. 核心页面

### 8.1 欢迎与路径选择

目标：不解释完整产品，只让用户选择开始方式。

布局：

1. 品牌名与一句价值说明。
2. 简化的六弦路径图：调音、和弦、节奏、第一首歌。
3. 主行动“从零开始”。
4. 次行动“直接使用工具”。
5. 底部隐私短句：“无需登录，学习记录保存在这台设备。”

不在此页请求麦克风权限，也不展示轮播介绍。

### 8.2 今天

首屏顺序：

1. 日期、问候与设置入口。
2. 当前阶段和路径进度。
3. 唯一主行动卡：标题、原因、预计时间、主要按钮。
4. 一个短练习建议。
5. 最近曲目和常用工具。

新用户主行动文案示例：

- 标题：`先让六根弦回到正确声音`
- 说明：`完成标准调音，后面的和弦才会听起来正确。`
- 元信息：`第 1 步，共 10 步 · 约 6 分钟`
- 按钮：`开始第一次调音`

不展示连续打卡、排行榜、空折线图或总学习时长。

### 8.3 调音器

视觉优先级：动作建议 > 音名与方向 > 六弦进度 > 专业数据。

状态布局：

1. 顶部：返回、标准调弦、自动/手动模式。
2. 中部：目标弦、当前音名、半圆偏差轨道和方向文字。
3. 轨道下：一句操作建议，例如“再拧紧一点，然后重新拨弦”。
4. 底部：六弦进度，每根弦同时显示名称和完成图形。
5. 折叠诊断：频率、cents、输入质量、A4。

稳定状态需保持短暂停留，避免边界闪烁。自动进入下一弦前提供 1 秒可感知过渡，并支持用户手动选择目标弦。

### 8.4 学习路径

- 顶部显示当前里程碑，不显示复杂能力树。
- 路径以连续的纵向节拍线呈现，当前节点使用品牌色。
- 每个节点显示课程名、预计时间、状态和必要工具。
- 未完成前置内容的课程不加锁，显示“建议先完成”并允许查看。

### 8.5 课程详情

- 固定顶部显示课程标题、步骤和退出。
- 一次只呈现一个步骤。
- 主体可包含一张动作图、最多三条说明和术语解释入口。
- 底部固定主按钮使用具体动词：`我找到第 6 弦了`、`开始调音`。
- 工具步骤直接切换到工具，不重复讲解工具操作。

### 8.6 练习会话

- 进入前显示目标、BPM、时长和“简单一点”选项。
- 会话中隐藏一级导航。
- 当前和弦占主视觉，下一和弦弱化显示。
- 四个拍点使用位置、大小和编号表达，不依赖闪烁。
- 暂停按钮保持在拇指可达区。
- 结束后只询问一次自评：轻松、刚好、有点难；问题细分为可选项。

### 8.7 曲谱库

- 顶部使用搜索，导入为明确但非主导的操作。
- 来源筛选使用：全部、本地、收藏、学习中、已完成、在线。
- 卡片明确显示 `内置`、`已导入`、`在线`，在线内容另显示是否可离线。
- 卡片优先展示标题、作者、难度、和弦和状态；许可信息在详情完整展示。

### 8.8 工具

不使用均匀的九宫格工具箱。调音器和节拍器作为两张大入口卡；和弦库作为横向内容入口。每个入口描述当前任务，而不是只写功能名。

## 9. 组件清单

| 组件 | 作用 | 关键状态 |
|---|---|---|
| `PrimaryActionCard` | 首页唯一下一步 | 默认、进行中、可恢复 |
| `PathProgress` | 表示路径阶段 | 未开始、当前、完成 |
| `LessonStep` | 单步课程内容 | 阅读、跟做、工具、完成 |
| `TunerGauge` | 音分方向与稳定状态 | 等待、偏低、偏高、调准、低置信度 |
| `StringSelector` | 六弦选择与完成进度 | 目标、检测中、完成 |
| `BeatRow` | 小节拍点 | 当前第一拍、当前普通拍、未播放 |
| `ChordDiagram` | 和弦图 | 标准、简化、逐弦检查 |
| `CapabilityChip` | 已会/待学习能力 | 已会、建议学习、仅信息 |
| `SourceBadge` | 曲谱来源 | 内置、导入、在线、不可访问 |
| `InlineRecovery` | 就地错误恢复 | 重试、去设置、替代路径 |

## 10. 文案规则

- 使用动作语言：`重新拨一下第 6 弦`，不用 `输入置信度低`。
- 专业值作为补充：`声音有点低 · -12 cents`。
- 错误说明包含原因与动作：`麦克风正被其他应用使用，请关闭通话或录音后重试。`
- 不使用“失败”“很差”等评价学习者的文案。
- 推荐必须附原因：`建议复习 G → D，因为上次在 56 BPM 标记为有点难。`
- 按钮使用具体结果，避免泛化的“确定”“下一步”。

## 11. 动效与触觉

- 页面切换：180–240ms，使用平移与淡入，不使用弹跳。
- 调音轨道：对输入做视觉平滑，状态由音频层结果决定，动画不定义业务状态。
- 调准：轨道收束、勾形出现，可选一次轻触觉反馈。
- 节拍：第一拍使用略大位移或尺寸变化，不使用高亮度闪烁。
- 开启减少动画后，保留状态切换但去除位移和连续动画。

## 12. 外观设置页

- 从右侧导航抽屉底部进入，不占一级导航位置。
- 顶部显示当前主题的缩略预览和名称。
- 预设主题以三张并列色板展示，选择后立即作用于当前页面。
- 自定义区提供强调色、明暗基底、内容密度、背景光晕和减少动画。
- `恢复默认外观`只重置视觉设置，不清除学习进度或练习历史。

## 13. 无障碍验收

- 所有交互目标不小于 48dp。
- TalkBack 顺序与视觉顺序一致。
- 调音状态只在目标弦或稳定状态变化时朗读。
- 和弦图提供完整文字按法，而不是逐个无上下文节点朗读。
- 200% 字体下主行动、状态文字和按钮不裁切。
- 灰度与常见色觉模拟下，偏低、偏高、调准仍可区分。
- 键盘可完成顶层导航、开始/暂停、调弦选择和退出。

## 14. 原型范围

`ui-prototype.html` 是首轮视觉与信息架构评审稿，包含：

- 今天、学习、练习、曲谱、工具五个顶层页面。
- 今天页到调音器的关键入口。
- 所有尺寸统一使用的右侧导航抽屉。
- 核心视觉 Token 与代表性组件。
- 极光夜、暖木、冰川和自定义强调色的实时切换。

原型不代表最终 Android 控件尺寸，也不验证音频、权限、返回栈和进程恢复。进入 Compose 实现前，应先完成五项导航、首次路径和调音默认模式三项可用性验证。
