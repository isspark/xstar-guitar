# 实施路线图

## 1. 实施原则

- 先验证高风险技术和内容，再扩展页面数量。
- 采用纵向切片打通“工具-知识-练习-曲目”，不按四层分别堆功能。
- P0 是发布阻断项；新增需求必须替换同等工作量，不能无条件扩张 MVP。
- 每个阶段只有达到退出标准后才能进入下一阶段。
- 单人开发参考 10 至 14 周；2 至 3 人小团队参考 7 至 10 周，不含应用商店审核时间。

## 2. 阶段总览

| 阶段 | 单人参考 | 核心交付 |
|---|---:|---|
| Phase 0 产品与技术尖峰 | 1 至 2 周 | 内容路径、DSP、节拍和导入可行性 |
| Phase 1 工程基线 | 1 至 1.5 周 | 工程、导航、本地数据、CI |
| Phase 2 工具闭环 | 2 周 | 调音器、节拍器、和弦基础 |
| Phase 3 学习与练习闭环 | 2 至 3 周 | 新手课程、练习、进度 |
| Phase 4 第一首歌与乐库 | 2 至 3 周 | 结构化曲谱、导入、收藏、在线 Provider 框架 |
| Phase 5 质量收敛 | 1.5 至 2 周 | 兼容性、性能、无障碍、安全 |
| Phase 6 封闭测试 | 1 至 2 周观察 | 真实用户验证与 RC |

## 3. Phase 0：产品与技术尖峰

### 3.1 任务

- 冻结零基础 8 至 12 节微课和第一首歌能力链。
- 准备至少 1 首原创、公版或明确授权的结构化练习曲。
- 建立标准音、真实吉他、噪声、泛音、滑音和削波样本集。
- 实现纯 Kotlin YIN/改进自相关音高检测原型。
- 实现 AudioTrack 音频帧节拍原型。
- 验证 Navigation 3 list-detail/supporting pane。
- 验证 PDF、图片以及候选 MusicXML/MXL 的 SAF 导入与安全限制。
- 确认最低 SDK、官方依赖版本和目标设备矩阵。

### 3.2 退出标准

- 至少两台代表性真机能稳定识别标准六弦主要范围，误差达到安静环境正负 5 cents 目标或形成明确降级。
- 节拍器连续运行 30 分钟无累计漂移，正常负载无可感知中断。
- 至少一条完整课程链与一首合法曲目通过吉他手复核。
- 恶意/损坏导入样本安全失败且无临时文件残留。
- MVP 支持格式和不支持格式清单已冻结。

## 4. Phase 1：工程基线

### 4.1 任务

- 创建 Kotlin + Compose 多模块工程、version catalog 和构建变体。
- 接入 Hilt、Room、DataStore、Navigation 3 和 Material 3 Adaptive。
- 建立主题、edge-to-edge、响应式导航和 Preview 基线。
- 建立领域模型、内容导入、稳定 ID 与构建期校验器。
- 建立测试 Clock/Dispatcher/Fake Repository。
- CI 执行编译、lint、静态检查、单元测试和内容校验。

### 4.2 退出标准

- Debug/Release 构建成功，版本锁定，无明文网络配置。
- 五个页面骨架可达，独立 back stack 与进程恢复符合设计。
- 内容首装幂等，Room Schema 导出和 Migration Test 可运行。
- 手机、平板、折叠窗口 Preview/截图测试骨架完成。

## 5. Phase 2：工具闭环

### 5.1 纵向切片 A：第一次调音

- 权限说明、授权/拒绝/永久拒绝流程。
- AudioRecord 生命周期、DSP 和调音 UI。
- 标准调弦逐弦模式、自动模式、噪声诊断。
- 第一课调用调音器并将完成结果写入进度。

### 5.2 纵向切片 B：第一次跟拍

- AudioTrack 节拍引擎、4/4、40 至 200 BPM 和重音。
- 预备拍、视觉同步、Tap Tempo、自动递增。
- 课程和练习复用统一引擎。

### 5.3 纵向切片 C：第一个和弦

- Em 等首批开放和弦数据、图示和文字说明。
- 和弦详情、收藏、最近查看、示范音。
- 从课程进入和弦，再进入练习并返回。

### 5.4 退出标准

- 调音、节拍和和弦在飞行模式下完整可用。
- 音频准确性、漂移、焦点、路由和资源释放达到质量基线。
- 权限拒绝不阻塞应用；退出调音页面不继续占用麦克风。
- TalkBack 可理解调音状态和和弦按法。

## 6. Phase 3：学习与练习闭环

### 6.1 任务

- 实现学习路径、课程步骤、前置关系和恢复位置。
- 录入并校对 8 至 12 节新手课程。
- 实现单和弦、双和弦转换、四和弦循环和节奏跟拍。
- 实现练习会话、暂停/退出、汇总、自评和历史。
- 实现能力证据、透明推荐和“今日 5 分钟”。
- 完成 Em、G、C、D、Am 等 5 至 8 个和弦内容。

### 6.2 退出标准

- 课程不存在断链和前置死锁。
- 完成、跳过、重做、退出和进程恢复状态一致。
- 5 名零基础测试者中至少 4 名无需指导即可开始第一次练习。
- 内容经至少一名合格吉他手复核，飞行模式可完成全部 P0 课程。

## 7. Phase 4：第一首歌与乐库

### 7.1 任务

- 建立结构化歌词和弦谱渲染及段落模型。
- 实现曲目详情、能力缺口、和弦跳转和返回上下文。
- 实现分段练习、整曲完成、BPM 和节拍器联动。
- 加入 3 至 5 首合法入门曲目。
- 实现 PDF/图片与已确认结构化格式的复制导入。
- 实现乐库、本地搜索、收藏、最近打开和存储管理。
- 使用 Fake Provider 完成在线搜索、分页、来源、许可和错误 UI。
- 仅在实际 Provider 完成准入评审后接入生产搜索。

### 7.2 退出标准

- 用户能完成“课程-练习-分段-整曲”闭环。
- 字体放大和小屏下，结构化和弦与歌词关系不乱。
- 导入失败可诊断、可重试且不残留文件。
- 每个内置或在线资源均有来源、作者、许可和署名。
- 网络断开或 Provider 失败不影响本地乐库。

## 8. Phase 5：质量收敛

### 8.1 任务

- 功能冻结，只修复缺陷和质量问题。
- 完成音频样本、真机、生命周期和长时间测试。
- 完成 Room Migration、SAF 安全、进程恢复和离线测试。
- 完成 TalkBack、最大字体、键盘、深色模式和减少动画测试。
- 完成 Macrobenchmark、Baseline Profile、内存和耗电分析。
- 配置发布签名、R8、备份规则、隐私政策、许可页面。
- 审查 Manifest、导出组件、权限和网络安全配置。

### 8.2 退出标准

- 无未解决阻断或严重缺陷。
- P0 自动化测试全通过，P1 通过率至少 98%。
- 无崩溃/ANR、启动、音频和内存达到 PRD 门槛。
- 指定设备、系统版本和音频路由完成测试。
- 所有发布内容许可证据完整。

## 9. Phase 6：封闭测试

### 9.1 范围

- 招募 20 至 50 名中文零基础用户，至少覆盖不同 Android 厂商。
- 观察首次调音、第一练习、和弦转换、第一首歌的流失点。
- 收集音频设备诊断时必须由用户主动导出，且不包含 PCM。
- 进行至少两轮“观察-修复-复测”。

### 9.2 发布退出标准

- 有真实零基础用户完成完整闭环。
- 无集中于某厂商或音频路由的阻断问题。
- 核心指标可解释，内容不存在明显错误或过大难度跳跃。
- P0 缺陷清零，剩余问题已接受并进入明确版本。

## 10. 依赖关系

```text
内容能力图 -> 课程/练习/曲目
音高尖峰 -> 调音器 -> 调音课程
节拍尖峰 -> 节拍器 -> 节奏练习 -> 曲目练习
和弦模型 -> 和弦库 -> 转换练习 -> 曲目需求
文件模型 -> SAF 导入 -> 本地乐库
Provider 准入 -> 在线搜索生产接入
工程基线 -> 所有 Feature
```

曲目资源许可和内容校对与客户端开发并行，但没有证据的内容不能进入发布包。

## 11. MVP 之后

按真实数据和反馈依次评估：

1. 优化新手路径流失点和内容质量。
2. 扩展节拍器拍号、细分、静音小节和自动速度计划。
3. 增加移调、Capo、自动滚屏和音频 A-B 循环。
4. 扩展横按、指板、音阶、指弹和电吉他路线。
5. 在真实样本足够且误判可控后增加单音/节奏评分。
6. 用户明确需要时提供数据导出或可选同步，保留免登录路径。
7. 核心留存和内容供给验证后再考虑教师、乐队和商业化。
