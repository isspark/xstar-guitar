# MVP Backlog

## 1. 优先级与完成定义

| 优先级 | 含义 | 发布规则 |
|---|---|---|
| P0 | 核心闭环、隐私、安全、数据或稳定性必需 | 任一未完成均不能发布 MVP |
| P1 | 构成完整体验的重要增强 | 原则上完成；延期需有替代方案 |
| P2 | 拉伸项或后续候选 | 不阻断 MVP，由真实反馈决定 |

每个 Story 的通用完成定义：

- 功能与验收标准一致，并覆盖加载、空、错误和恢复状态。
- 新增业务逻辑有自动化测试；内容通过构建期和人工校验。
- 支持离线的功能已在飞行模式验证。
- 核心 UI 通过手机、较宽窗口、字体放大、深色和 TalkBack 检查。
- 不引入敏感日志、无依据权限或未评审在线资源。
- 相关文档和 ADR 已同步更新。

## 12. 建议首个迭代

第一个可演示纵向切片不应只是首页骨架，建议包含：

1. `A-01`、`A-02`、`A-03`、`A-05` 的最小工程基线。
2. `B-01` 的首次行动入口。
3. `C-01` 至 `C-05` 的标准调音器最小实现。
4. 一节“认识六根弦与第一次调音”本地课程。
5. 调音结果写入课程进度并在首页展示下一步。

该切片验证权限、实时音频、内容、进度、导航和离线六个核心架构边界，为后续功能提供可信基线。
